## Module Documentation Guidelines

When documenting a module:

1. **Purpose** — What the module does
2. **API Surface** — Public interfaces/exports
3. **Dependencies** — What it depends on
4. **Dependents** — What depends on it
5. **Invariants** — Rules that must not change
6. **Testing** — How to test in isolation
